# 目标架构

## 分层

```text
任务/导航/遥控
      |
安全监督与策略调度（平台无关）
      |
导航 | 深度视觉 | RL/运动策略（官方基线 + 独立升级模块）
      |
统一机器人接口：状态、IMU、感知、关节命令、生命周期、故障
      |
平台适配层
  ├─ x5: Linux ROS 2 + SocketCAN/USB2CAN
  └─ s100: Linux ROS 2 + USB2CAN 或 MCU CANHAL/CAN2IPC 桥
      |
23 关节 / IMU / D435i / 3D LiDAR
```

## 关键设计规则

1. `upstream/` 永远视为只读第三方来源；补丁和适配代码放在后续项目自有 `src/`。
2. 统一接口不暴露 `can0-can3` 等板卡细节。X5 和 S100 的启动配置、设备映射、健康检查和回退脚本分别保存。
3. 安全监督位于策略输出和执行器命令之间，至少覆盖超时、NaN/Inf、关节限位、速度/转矩/电流限制、IMU 异常、通信丢帧和人工停机。
4. 导航输出不能直接变成关节命令；必须经过速度命令约束、策略调度和运动状态机。
5. 证据按 `板卡/能力/日期/测试编号` 保存，日志与配置必须能对应到精确代码版本。

## 基线与升级隔离

- `baseline`：仅做使官方能力在指定硬件和版本上可重复运行所需的最小适配。
- `candidate`：任何性能、模型、感知或安全算法升级。
- 评估采用相同输入、指标和安全限制；只有候选在离线、仿真、台架和受控实机阶段依次通过，才可提升为新基线。

## 初始指标

- 系统：启动成功率、节点存活、接口频率、时延、丢帧、CPU/BPU/GPU/内存。
- 控制：200 Hz 周期抖动、50 Hz 推理时延、命令超时、关节跟踪误差、故障停机时间。
- 视觉：深度有效像素率、预处理频率、编码时延、输出维度和异常帧处理。
- 导航：定位漂移、地图一致性、规划成功率、航点误差、重定位时间和安全停机。
- RL：仿真回报、跌倒率、速度跟踪、能耗代理、sim2sim 差异与策略确定性。
